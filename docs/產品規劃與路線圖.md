# 棲光小島｜產品規劃與路線圖

更新：2026-10-27。這份整理產品定位、和 Forest 的比較、接下來要優化的體驗，以及分階段的開發路線，給團隊和合作夥伴討論用。

## 1. 定位：你的專注，守護真實的動物

Forest 是「專注就長出一棵樹」，簡單、一看就懂。棲光小島不跟它比同一件事做得更好，而是走它沒有的路：**把專注和真實世界的保育連在一起**。

- 主角是台灣（之後是日本等國家）的保育類動物，有棲息地、保育等級、立體地圖。
- 專注累積的點數會修復森林，動物會回來、族群會長大，有長期的養成目標。
- 失敗很溫柔：10 秒內免費取消、可以暫停、放棄後有安慰頁；還有時間守護幫忙少滑手機。

## 2. 和 Forest 的比較

### 我們的優點

| 面向 | 棲光小島 | Forest |
| --- | --- | --- |
| 主題意義 | 在地保育類動物，帶生態教育與在地認同 | 種樹，主題單純但抽象 |
| 長期養成 | 專注 → 修復工程 → 動物回來 → 族群長大 → 下一個國家 | 收集樹種、種滿森林 |
| 對失敗溫柔 | 10 秒免費取消、可暫停、安慰頁 | 離開就枯死、不能暫停 |
| 數位健康 | 時間守護：打開想少用的 App 時先深呼吸 | 沒有同等功能 |
| 免費功能 | 深度專注、統計趨勢、環境音、延長計時都免費 | 很多在 Plus 付費版 |
| 隱私 | 不用註冊，資料只在手機 | 需要帳號 |
| 回顧與獎勵 | 上週回顧、每日／每月挑戰、寶箱、成就 | 有成就，回顧較少 |

### 我們的缺點

| 面向 | 棲光小島現況 | Forest | 影響 |
| --- | --- | --- | --- |
| 美術 | 只有石虎一張正式圖 | 幾百種精緻的樹 | 最大：收集型 App 靠美術吸引人 |
| 內容量 | 2 個國家、27 種動物 | 非常多樹種、季節活動 | 玩久了缺新東西 |
| 多人與社群 | 沒有伺服器，好友、排行、邀請還不能用 | 一起種樹、排行、邀請 | 少了口碑與互相督促 |
| 雲端同步 | 沒有，換手機要手動匯出 | 帳號同步、多裝置 | 資料遺失就流失使用者 |
| 平台 | 只有 Android | iOS、Android、外掛、小工具 | 少一半以上潛在使用者 |
| 語言 | 只有繁體中文 | 多國語言 | 進不了海外市場 |
| 真實回饋 | 沒有 | 和公益組織種真的樹 | 少一個情感賣點 |
| 收費 | 內購還沒串接 | 成熟的收費模式 | 還沒有收入 |
| 學習門檻 | 系統多：工程、族群、區域、金幣、寶石、任務、成就 | 一句話就懂 | 新手抓不到重點 |
| 專注當下的回饋 | 剪影慢慢變清楚 | 看著樹長大 | 滿足感比較弱 |

## 3. 降低學習門檻

問題不在單一功能太難，而是一開始就把所有系統攤開。

1. **功能逐步解鎖**：第一天只有「專注 → 遇見動物」。完成第 1 次才出現我的小島和修復工程，第 3 次出現每日挑戰，第一次開寶箱出現商店和金幣，之後才是寶石、成就、時間守護，台灣修完才出現區域切換。出現時選單旁標「新」。
2. **大廳只放一句「下一步」**：例如「再專注 40 分鐘，步道就修好，穿山甲會回來」。
3. **一次只教一件事**：第一次用到某個功能時才跳一個小提示，看過就不再出現。
4. **少講內部名詞**：成長點數會自動投入，畫面上不再提，玩家只需要知道金幣和寶石。
5. **合併選單**：專注紀錄和我的歷程合成「紀錄」，大自然交響樂放進小島或設定，成就放進個人資料；主選單從 13 項減到 7～8 項。

## 4. 強化專注當下的回饋

1. **分段的靠近劇情**：每 25% 一個小事件（地上出現足跡 → 草叢在晃 → 探出頭 → 完整現身），配輕動畫，可選擇震動。
2. **當下就看得到工程進度**：例如「這次已經 +18 點 → 步道 61%」，數字跟著跳。
3. **動物小知識**：專注到一半出現一句，例如「石虎是台灣唯一的原生貓科動物」。
4. **遇見的瞬間更有儀式感**：結束時畫面壓暗、剪影轉成彩色、動物抬頭。
5. **鎖屏也看得到進度**：Android 常駐通知加進度條；iOS 用動態島。
6. **場景跟著時間變**：光線從清晨變午後，專注越久森林裡的小生物越多。

## 5. 技術路線：要不要改成原生 App

目前已經是能上架的 App：介面用網頁技術做，外面包原生外殼（Capacitor），時間守護、深度專注、通知都是原生程式。Google Play 和 App Store 都接受這種做法。

| 做法 | 優點 | 缺點 |
| --- | --- | --- |
| 維持現狀、持續最佳化 | 成本最低，一份程式兩個平台 | 動畫、3D 在低階手機較吃力 |
| 改 React Native | 介面換成原生元件、手感更好；遊戲規則（存檔、計時、經濟）可以直接沿用 | 畫面要重寫 |
| 完全原生（Kotlin＋Swift） | 手感、效能最好 | 兩份程式，成本最高 |

**建議**：先用現在的版本驗證產品；如果封測回饋確定體感是問題，再改 React Native。遊戲規則已經寫成獨立的純邏輯，可以直接搬。

## 6. 怎麼脫穎而出

1. **和保育單位合作，產生真實影響**：全體玩家累積一定專注時數，就捐款支持保育計畫（例如石虎、台灣黑熊），App 裡顯示「大家已經幫助了多少」。
2. **跟著真實自然曆辦活動**：八色鳥 4～9 月回台灣、螢火蟲季、紫斑蝶遷徙，季節限定動物與活動。
3. **知識是核心體驗**：圖鑑放真實叫聲、棲息地、保育故事；延伸到教育市場，老師帶全班一起修一座島。
4. **溫柔的數位健康**：主打「不焦慮的專注」，和「樹會枯死」的壓力感區隔。
5. **合作取代競爭**：多人模式是好友一起修同一座島，而不是比排行。
6. **每個國家找在地夥伴**：例如日本版和西表山貓的保育團體合作。

## 7. 分階段路線圖

| 階段 | 重點 | 為什麼放在這裡 |
| --- | --- | --- |
| 0. 內部測試（現在） | 修 UI／UX、確認主循環好玩、建立美術流程、放入幾隻正式動物 | 先確定好不好玩 |
| 1. 小規模封測（Android，20～50 人） | 降低學習門檻、台灣主線動物正式美術、存檔改原生儲存、當機回報、隱私權政策 | 用真實玩家回饋調整 |
| 2. 正式上架 Google Play（台灣） | 雲端帳號與同步、內購、好友／邀請／排行接上伺服器、拿掉假資料與測試工具 | 有伺服器，多人功能才有意義 |
| 3. 擴張 | iOS（螢幕使用時間、動態島）、英文與日文介面、日本正式內容、季節活動、保育單位合作 | 核心穩了再擴大市場 |
| 4. 評估 | 依數據決定是否改 React Native、開哪些新國家 | 避免太早投入大成本 |

## 8. 待決定事項

1. 封測人數與招募方式（朋友、學校、社群）。
2. 伺服器選擇（例如 Firebase 或 Supabase）與預算。
3. 收費方式：寶石內購、Plus 訂閱，或兩者並行。
4. 優先接洽的保育單位與合作方式。
5. 美術量產的分工與時程（台灣主線 10 種 × 3 個成長階段＋商店物種各 1 張）。
