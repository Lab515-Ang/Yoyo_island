# 棲光小島｜動物動態（網格骨架）製作規範

建立：2026-10-28。來源：石虎（`leopard_cat`）實作與 A8s 實機驗證（過程見 `docs/測試-RiveMCP.md` 第 8 節）。

**適用**：棲光小島的動物動態一律用自己的「分層部件＋網格骨架權重」（WebGL 播放），每一隻都必須照這份做。

**決定（2026-10-28）**：不用 Rive／Spine。RiveMCP 試用結果：效能跟自製版差不多（A8s 兩版都 60 fps、CPU 相近），但它不會拆圖、權重匯不進去，播放器多 2.6 MB，授權價格不明（比較見 `docs/測試-RiveMCP.md`）。條文後面的「（因為…）」是石虎實際踩過的破綻，不要省略。

**用語**
- **主圖**：正側面朝右的完整動物圖，所有部件都從它切出來。
- **剝層圖**：請 GPT 對主圖「只改一處」的編輯圖（例如拿掉近側腿），用來補畫被擋住的部分。
- **近側／遠側**：靠近觀看者／被擋在後面的那一側（腿、耳朵）。
- **網格**：每個圖層切成三角形，頂點依權重跟著骨頭變形（線性混合蒙皮）。
- **權重**：一個頂點各跟幾根骨頭動多少（加總 = 1）。
- **肚子線**：身體下緣、腿開始的那條線。

## 1. 哪些畫面會動

| 畫面 | 同時會動 | 規定 |
| --- | --- | --- |
| 圖鑑特寫 | 1 隻 | 完整網格 |
| 探索（望遠鏡） | 1 隻 | 完整網格 |
| 個人小島 | 最多 6 隻（`Island.tsx` 的 `SPOTS`） | 6 隻畫在**同一個 WebGL 畫布**；網格可放寬、貼圖可縮小 |
| 專注紀錄、旅程、分享卡、商店等 | 0 | 單張圖（＝網格圖層在靜止姿勢合成的結果） |

- 不可以每隻動物各開一個 WebGL 畫布（Chrome／WebView 約 16 個上限）。
- 看不到的動物不畫；離開畫面、App 在背景、螢幕關閉時停止。
- 定格感（每秒 8 格、畫面沒變就不重畫）是建議預設：A8s 實測 CPU 約減半（走路 68% → 35%）。

## 2. 製作流程

```
主圖（GPT，正側面） → 剝層圖（GPT，一次只改一處）→ 對齊、校色 → 找範圍
 → 切部件（硬切片圖層，23 層）→ 合成網格圖層（12 層）→ 網格＋權重
 → 離線檢查（半尺寸貼圖）→ 手機實機檢查 → 輸出 App 素材
```

腳本（石虎版）在 `tools/animal-rig/`（用法見該資料夾的 README）；工作檔（主圖、剝層圖、輸出）放 `.forge/`，不進 git：

| 步驟 | 腳本 |
| --- | --- |
| GPT 提示（主圖、剝層、局部重畫） | `prompts/` |
| 對齊剝層圖、校色 | `register.py` |
| 找範圍 | `masks.py` |
| 切硬切片部件 | `rig.py` → `layers/`、`rig.json` |
| 局部重畫換進主圖 | `patch_master.py` |
| 網格圖層＋PSD | `make_mesh.py` → `mesh_layers/`、`leopard_cat_mesh.psd`、`rig_mesh.json` |
| 網格＋權重＋播放頁 | `make_mesh_player.py` ＋ `m_template.html` → `mesh.json` |
| 離線渲染檢查 | `mesh_pose.py`（`HALF=1`）、`walkcheck.py`、`check_poses.py`、`pose.py` |

## 3. 主圖

- 正側面朝右，四條腿都看得到（近側腿在前、遠側腿稍暗在後），白底，畫面置中留邊。
- 用正式動物圖當參考請 GPT 重畫；風格：霧面黏土、低彩度。
- **主圖確定後就是唯一的像素來源**。之後局部重畫也只能「換一塊」進主圖（見第 4 節最後一條）。

## 4. 剝層圖（GPT 編輯）

- 一次只改一處，提示開頭固定寫：「This is an EDIT of the reference image. Output the SAME image… Change ONLY …」，並要求同樣的姿勢、位置、比例、顏色、白底。
- 必做（E2 除外；鳥、貓頭鷹的對應清單見美術清單 B-1）：

| 代號 | 內容 | 用途 |
| --- | --- | --- |
| E1 | 拿掉近側兩條腿（只拿肚子線以下），補畫遠側腿與肚子 | 遠側腿被擋住的部分 |
| E3 | 拿掉頭，脖子頂端收圓，補畫頭後面的脖子 | 頭轉開時露出的脖子 |
| E4 | 拿掉兩隻耳朵，補畫頭頂 | 耳朵底下的頭皮 |
| E5 | 閉眼 | 眨眼 |
| E7 | 頭轉向鏡頭：只轉頭（脖子跟著自然轉），臉正對觀看者、兩隻眼睛都看得到；身體、腿、尾巴完全不動 | 看鏡頭的動作：整組頭部圖層換成這張的頭，脖子交界照 5.6 用 E3 墊底（2026-10-28 新增，**每種動物、每種體型都要有，魚、蝴蝶除外**；切法待第一隻實作確認） |
| （E2） | 拿掉四條腿 | 石虎沒用到（GPT 把肚子畫胖） |

- **禁止讓 GPT 分開畫各個部件再組裝**。（因為：第一、二版這樣做，關節被畫成玩具插銷／插槽，圖層順序也錯。）
- 提示裡不要寫「joints」「rounded ends where limbs attach」，GPT 會畫成玩具接頭。
- 對齊用 OpenCV ECC 仿射，位移應 < 2px、相關係數 > 0.89；再用沒改到的前景區域逐通道校正色調。
- **找範圍一律跟「原主圖」比**。主圖之後若局部重畫，原主圖要備份（`side/generated_orig.png`），`masks.py` 讀備份。（因為：剝層圖是對原主圖做的，跟新主圖比會把重畫的地方誤判成差異，眼睛範圍一度從 7,026 變成 11,753 像素。）
- **局部重畫**（例如後腿根）：請 GPT 對原主圖只改那一小塊 → 對齊 → 只把指定矩形換進主圖、邊緣羽化約 30px（`patch_master.py`）→ 檢查接縫。

## 5. 切部件（硬切片圖層）

### 5.1 總原則
1. **看得到的像素一律用主圖**；只有被擋住、動起來才會露出的地方用剝層圖。
2. 相鄰部件在內部接縫**互補、硬邊**（不羽化）；靜止時合起來必須等於主圖。
3. **半透明邊緣底下要是同樣的像素**：上層的柔化邊緣底下，下層必須是主圖同一處的像素，不能是剝層圖或空白。（因為：縮成半尺寸後邊緣變半透明，底下不同就透出一條線。頭的邊緣內側 8px、耳根內側 6px 都照這條保留主圖。）
4. 外輪廓去白邊：遮罩先往內縮 2px 再柔化 0.8px。（因為：白底去背的邊緣 1～2px 混了白色，疊在深色部件上會變白邊。）
5. 範圍遮罩要清碎片：開運算、只留最大塊、補洞；每層輸出前再清一次孤立碎片。

### 5.2 圖層與階層（由後往前）
```
leg_back_far（paw / lower / upper）
leg_front_far（paw / lower / upper）
body
tail（tail_3 / tail_2 / tail_1）
leg_back（paw / lower / upper）      ← 近側大腿壓在身體上
leg_front（paw / lower / upper）     ← 近側肩膀壓在身體上
neck
  head：ear_far / head_base / eye_open / eye_closed（預設隱藏）/ jaw / ear_near
```
- **近側腿、頭在身體前面**，遠側腿在身體後面。（因為：第二版為了藏接縫把近側腿和頭塞到身體後面，看起來像豆子插柱子。）

### 5.3 關節
- 每個關節的父段、子段都含一個**以轉軸為圓心**的圓盤；半徑＝該處部件的半寬（距離轉換自動量）＋1.5px。
- 腿、尾巴的切線要**垂直於腿／尾巴的方向**（尾巴沿中心線量距離分節）。（因為：斜的腿用水平線切，切面比圓盤寬，轉動時邊角露出來。）
- 子段往父段底下多伸 6px。
- 頭的轉軸放在**後腦與頸椎的接點**，點頭時後腦不動。（因為：轉軸放在下巴附近時，低頭會在後頸拉出大洞。）

### 5.4 腿
- **近側腿**：範圍＝主圖與 E1 的差異、清碎片、只取肚子線以下；有沾到別的部件（例如遠側腳掌）要沿主圖輪廓手動切掉。
- **近側腿的髖／肩圓盤整片保留**（羽化 24px 融進身體）。（因為：試過在肚子線以下挖掉 2px、12px，也試過柔性淡出，都會在腿頂端留下切口，縮小後變成細線、比原本更明顯。）
- **遠側腿**：
  - 只取「主圖也有東西」的範圍（排除 E1 胖出來的肚子）。（因為：E1 的肚子比主圖胖、偏白，遠側腿一擺就甩出一塊淺色方塊。）
  - 腿本身＝肚子線下 6px 以下、不是奶油色的部分；往上只延伸「腿本身寬度」的柱狀 25px 藏在身體後面。
  - 扣掉跟近側大腿重疊的部分（那是近側大腿的像素）。
  - 看得到的用主圖；被近側腿（含髖部圓盤）蓋住的像素，一律用「看得到的遠側腿」最近的顏色往外延伸。（因為：那裡在主圖是近側大腿的奶油色摺邊，腿一擺就露出一撮淺色。）
  - 圓盤只留在腿本身範圍內，不包身體、肚皮。
- 遠側腿用 E1 的地方，跟主圖的交界要羽化（約 3px）。

### 5.5 身體與肚子
- 身體 = 其他部件的互補。肚子線以下：用主圖的自然輪廓扣掉腿，**不可以用水平直線切**。
- 肚子線以下 40px 內、跟身體相連的**奶油色肚皮（低飽和、高亮度）歸身體**，不歸腿；胯下細碎的奶油色要濾掉。（因為：分給遠側腿時，身體輪廓少一塊，腿一擺肚子下緣出現階梯。）
- 近側腿正後方的身體用 E1 的肚子墊底。

### 5.6 頭、脖子、耳朵
- **耳朵用手描的交界線**（耳朵跟頭、脖子、另一隻耳朵的分界，從主圖細格線放大量），外輪廓由白底決定。**不要用主圖與 E4 的差異當耳朵範圍**。（因為：兩隻耳朵在差異遮罩裡連成一塊，兩個耳朵圖層都含兩隻耳朵，一動就分裂；差異也很雜，會抓到頭頂的毛或在耳緣破洞。）
- 頭本體在耳朵正下方換成 E4（去耳）的頭皮與輪廓，頭皮要完整、不能留縫；耳根內側 6px 保留主圖。
- 遠側耳朵被近側耳朵擋住的部分，往後延伸約 30px，顏色用遠側耳朵最近像素；延伸不可超出遠側耳朵頂緣的延長線。（因為：近側耳朵擺動時兩耳之間會露白；顏色用 inpaint 會被黑色背景污染。）
- 脖子：看得到的用主圖；被頭、耳朵擋住的地方只用 E3（去頭）。**脖子在耳朵位置不可取主圖**。（因為：低頭時頭後面出現「鬼耳朵」。）耳朵拿掉後脖子頂端的缺口，用閉合補平輪廓、顏色 inpaint。
- 頭底下：E3 與主圖的交界羽化，頭邊緣內側 8px 保留主圖。
- 嘴巴內側（深玫瑰褐）畫在頭本體上、只在下巴範圍內，張嘴才露出。

## 6. 網格圖層（12 層）

- 每條腿、尾巴、**身體＋脖子**各合成一塊；頭、兩隻耳朵、張眼、閉眼、下巴分開。
- 網格版的脖子另外輸出：頭底下只用 E3 的自然脖子輪廓。（因為：硬切片版為了蓋縫墊在喉嚨的那塊，低頭時會露出直邊。）
- 每層往「靜止時被上層完全蓋住」的地方多延伸 10px（`BLEED`），顏色取自己最近的像素。
- 合成後 PSD 要跟主圖比對：平均差 ≤ 1.5（石虎 1.17）、p99 ≤ 10（石虎 8）。

## 7. 網格與權重

- 網格：特寫／探索每 12px 一格；小島（52～96px 顯示）放寬到 24～32px。每頂點最多 4 根骨頭、權重加總 1。
- 骨頭 21 根：
  ```
  body ─┬─ neck ── head ─┬─ ear_near / ear_far / jaw
        ├─ tail_1 ── tail_2 ── tail_3
        └─ <leg>_upper ── <leg>_lower ── <leg>_paw（四條腿）
  ```
  起點＝硬切片版各段的轉軸。
- **鐵則：疊在一起的圖層，同一個位置的權重必須一樣**，才會一起變形、不露縫。

| 部位 | 權重規則（石虎數值） |
| --- | --- |
| 脊椎場（身體＋脖子、頭、眼睛共用） | 只分 body、head 兩根：head 權重＝離身體核心距離 ÷（離身體核心＋離頭），再柔化 20px。脖子過渡帶往胸口留到 y≈800。neck 骨頭不直接帶權重 |
| 身體在近側腿根、尾巴根 | 以轉軸為圓心、半徑內全跟、外圈漸變回脊椎場。半徑要**大於「腿／尾巴和身體重疊處離轉軸最遠的距離」**（後腿 185、前腳 165、尾巴 110px；漸變 90／90／70px） |
| 身體在腿根 | **只跟大腿那一根**，不跟小腿、腳掌。（因為：小腿一彎，肚皮被拉歪，前腳上方出現水平斷層。） |
| 腿 | 壓在身體上的部分＝身體的權重（只跟大腿）；離開身體輪廓 40px 內漸變接上整條腿的鏈；關節前後漸變半寬：髖 45、膝 32、踝 22px |
| 尾巴 | 沿中心線：根 40、中 30、尖 30px |
| 耳朵 | 按「離看得到的頭皮多遠」漸變：近側 120px、遠側 70px（耳根黏住、耳尖彎過去）。不要只看離耳根轉軸多遠 |
| 下巴 | 嘴角那端漸變 25px |
| 眼睛 | 直接跟頭，不用網格變形 |

## 9. 驗收（每隻動物都要做，缺一不算完成）

1. **靜止比對**：硬切片合成、網格 PSD 合成都要跟主圖比（第 6 節門檻）；差異只能在外輪廓那 2px。
2. **離線放大檢查**：一律用 `HALF=1`，也就是**跟手機一樣的半尺寸貼圖、先預乘再內插**。（因為：用原尺寸貼圖檢查時一切正常，半尺寸才出現的白線、斷層全被漏掉。）
   - 走路一個循環至少 4 個時間點（0、¼、½、¾），裁前腳上方、後腿根、肚子下緣、脖子。
   - look、sniff、張嘴、眨眼、甩尾兩端、耳朵抖動最大角度。
   - 找到破綻時，**逐層單獨渲染**（其他層藏起來、洋紅底）找出是哪一層，再查那一層在主圖對應位置的像素來源。
3. **手機實機**（A8s）：
   - 先確認：手機已解鎖、沒有專注在進行（`watchActive=false`）、使用者這段時間不會碰手機。
   - 每次點擊前確認 Chrome 在前景；點了按鈕後**看截圖確認按鈕狀態**（走路是否真的開了）。
   - 走路連拍 10 張、耳朵抖動要涵蓋抖動那 0.6 秒。
   - 結束後 `svc power stayon false` 改回設定；畫面被切走就立刻停止。
4. 每次修改後都重跑 1、2；**修完更糟就還原**，記下試過什麼、為什麼不行。

## 10. 輸出

- 貼圖：各層縮成半尺寸 webp（quality 88～90），**縮圖用 BOX，不用 Lanczos**。（因為：Lanczos 在硬邊振鈴，關節圓弧上出現一圈亮線。）
- WebGL 貼圖要預乘 alpha（`UNPACK_PREMULTIPLY_ALPHA_WEBGL`），混合用 `ONE, ONE_MINUS_SRC_ALPHA`；片段著色器裡 UV 超出 0～1 的部分輸出透明。
- JSON 一律用 UTF-8 寫入。（因為：Windows 預設 cp950，含中文備註的檔案會讀不回來。）
- 容量目標：每隻壓縮後 ≤ 120 KB（貼圖約 70 KB＋網格資料；座標、權重用整數存、網格放寬）。石虎目前未壓縮 460 KB（網格資料 382 KB，gzip 後 132 KB）。100 隻約 10 MB。

## 11. 破綻對照表

| 看到的破綻 | 原因 | 對策（條文） |
| --- | --- | --- |
| 關節米白圓柱、身體有洞 | GPT 分開畫部件 | 4 |
